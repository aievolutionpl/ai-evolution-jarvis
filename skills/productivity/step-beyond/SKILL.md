# Step Beyond Skill

Finish what was asked, then add the one thing the person would have asked for next. This is
a finishing discipline, not a licence to expand scope: the requested deliverable always
lands first, complete and verified, before any extra layer exists.

## When to Use

- A deliverable is finished and the obvious next step is visible from the work itself.
- A page, image, post, or document is "done" but plainly unfinished in its context.
- The user is iterating fast and expects the agent to keep up without instructions.

## Prerequisites

- None. This changes how work is completed, not what tools are used.

## How to Run

1. Deliver the ask. Nothing else happens first.
2. Add at most one extra layer that the same context implies.
3. Say what was added in one line, separate from the delivery.

## Quick Reference

- **Level 1 — Polish, always:** detail, composition, light, pacing, real copy. Never hand over
  a bare artifact in a void.
- **Level 2 — Extend, when it clearly fits:** the logical continuation (page → contact page,
  post → hook variants, image → second crop).
- **Level 3 — Anticipate, when the next request is obvious:** build it now and mention it once.
- **Stop signal:** "just X", "nothing more", or a rushed mode — deliver exactly the ask.

## Procedure

1. **Satisy the literal request** and verify it (open the file, run the test, read the render).
2. **Pick one level, not all three.** Choose the level the work itself argues for, and only
   when the extra layer costs a fraction of the original task.
3. **Respect domain defaults** where the person has already stated a preference — reuse their
   brand rules, formats, and language instead of inventing new ones.
4. **Communicate the split.** Lead with the delivery as done; then a single short line naming
   the extra layer, so the person can ignore it without losing the ask.
5. **Never silently rewrite scope.** Extra work is additive; the requested artifact keeps its
   agreed shape.
6. **Escalate only on cost.** If the deeper layer would take substantially longer than the ask,
   offer it instead of doing it.

## Pitfalls

- Building a product where a page was requested — one level deeper, not five.
- Burying the delivered artifact under a wall of "while I was at it".
- Adding a layer that contradicts a stated preference (wrong language, wrong format).
- Treating "just do X" as an invitation; it is the off switch.
- Extending work the person will throw away, because the ask itself was exploratory.

## Verification

- The requested artifact exists, is complete, and is verified — independent of the extras.
- The extra layer is one coherent improvement, described in one line.
- The person can accept the delivery without reading past the first block.
